# ParableLabs — Rubric & Sponsor-Judging System

Data model + page spec for the judging module. Extends the existing Prisma schema (Users, Hackathons, Submissions, Badges) and slots into the AI Evaluation module already in progress. Written to be pasted into your AI coding tool alongside the schema file.

---

## 1. Core idea

Three things that were previously implicit become explicit, first-class entities:

1. **The rubric is organizer-defined per hackathon**, not a fixed platform-wide scoring field. Each hackathon has its own set of weighted dimensions.
2. **A submission can belong to multiple tracks** (general judging + N sponsor tracks), and each track can have its own judges who only see submissions opted into their track.
3. **AI produces a baseline score per dimension first.** Human/sponsor judges see it, can agree or override, and every override is logged — this is what makes the AI Evaluation module trustworthy instead of a black box.

---

## 2. Prisma schema additions

```prisma

  HEAD_JUDGE      // full visibility, confirms final winners
  JUDGE           // scored across all general-track submissions
  SPONSOR_JUDGE   // scoped to one or more specific tracks only

  id            String    @id @default(cuid())
  submissionId  String

  track         Track     @relation(fields: [trackId], references: [id])

}

  id            String    @id @default(cuid())
  submissionId  String
```

`Submission` gains relations to `SubmissionTrack[]`, `AIEvaluation[]`, `JudgeScore[]`, and `WinnerSelection[]`. `Hackathon` gains `Track[]` and `RubricDimension[]`. `User` gains `JudgeAssignment[]`.

## 3. Scoring logic

**Per-dimension score, per judge type:** each judge assignment scores each submission on each in-scope dimension, 0–`maxScore`.

**Weighted score for a submission on a track:**
```
weightedScore = Σ (dimension.weight × (averageScoreForDimension / dimension.maxScore)) × 100
```
where `averageScoreForDimension` is the mean of all `JudgeScore` entries for that dimension (AI counts as one input, weighted separately — see below).

**AI-vs-human blending (define explicitly, don't leave implicit):** the AI score is not silently averaged in as if it were another judge. Two supported modes, chosen per hackathon at rubric-setup time:
- **AI-assist mode (default):** AI score is shown as a pre-filled starting point per dimension; only human `JudgeScore` entries count toward the final weighted score. AI is a tool, not a voter.
- **AI-blended mode:** AI counts as one scoring input alongside human judges, with its own configurable weight (e.g., AI = 30%, judges = 70% of that dimension's score). Use this only where a hackathon explicitly opts in — it changes the trust story and should be visible to participants.

**Override flag:** a `JudgeScore` is marked `isOverride = true` automatically when it deviates from the AI baseline for that dimension by more than a threshold (e.g., 2 points on a 10-point scale, configurable). This is what lets you build a "how often do judges disagree with the AI" analytics view later — useful for improving the AI Evaluation model over time.

---

## 4. Access model

| Role | Sees | Can do |
|---|---|---|
| Head Judge | All tracks, all submissions, all scores | Score anything, confirm final winners, override any dimension weight mid-event (with confirm dialog) |
| Judge | All tracks (general judging pool) | Score any submission on unlocked dimensions |
| Sponsor Judge | Only submissions opted into their assigned track(s) | Score only their track's dimensions, select winners for their track's prizes (drafts only — Head Judge confirms) |
| Mentor Judge | Same scoping as Judge, but flagged separately so mentee submissions can be excluded from their queue to avoid conflict of interest |

Sponsor judges are invited by email and may not have a full ParableLabs account — `JudgeAssignment.userId` is nullable and the invite flow issues a scoped access link/token, matching how Devfolio hands sponsors a judging URL without requiring a full account.

## 5. Pages

### Organizer: `/hackathons/[id]/rubric`
- List of dimensions grouped by scope (General / per-track), each showing name, description, weight %, max score.
- **Add dimension** → form: name, description (this is the guidance text judges will read while scoring — make it required and specific, not a placeholder), weight, max score, scope (General or a specific Track). Live-updating "weights sum to 100%" indicator; block save if it doesn't add up, with the specific dimension(s) to adjust highlighted.
- **Edit** inline for name/description; weight changes after judging has started trigger a confirm dialog: "Judging is already in progress for 12 submissions. Changing this weight will recalculate all existing scores. Continue?"
- **Delete** a dimension → confirm dialog naming it and stating how many existing `JudgeScore`/`AIEvaluation` rows will be removed.
- **AI mode toggle** (AI-assist vs AI-blended) set once per hackathon, shown prominently since it affects the trust model — changing it after judging starts should be a hard confirm with a warning, not a quiet toggle.

### Organizer: `/hackathons/[id]/tracks`
- Grid of tracks (General + sponsor tracks), each showing sponsor logo, prize count, submission count, assigned judge count.
- **Add track** → form: name, sponsor name/logo upload, description, then inline add of one or more prizes (name, value, max winners).
- **Delete track** → confirm dialog: if submissions have already opted in, warn how many and that their sponsor-track scores will be lost.

### Organizer: `/hackathons/[id]/judges`
- Table: judge name/email, role, scoped track(s), invite status, submissions scored / assigned.
- **Add judge** → form: email, role (dropdown), track scope (multi-select, only enabled/relevant for Sponsor Judge / Mentor Judge). Sends an invite email with a scoped link.
- **Remove judge** → confirm dialog: if they've already submitted scores, state clearly whether those scores are kept (recommended default: keep scores, just revoke future access) or discarded — make this an explicit choice in the dialog, not a silent default.

### Judge / Sponsor Judge: `/judging/[hackathonId]`
- Submission queue scoped to the judge's access (all tracks for Judge/Head Judge, assigned track(s) only for Sponsor Judge).
- Search bar (by project name) + filter by track — mirrors Devfolio's judging search/filter pattern.
- Each row: submission name, team, track badges, AI baseline score (small, muted, mono font — a preview not the headline), your-score status (Not started / In progress / Complete).
- Empty state if no submissions are in scope yet: "No submissions in your assigned track yet — check back once teams start submitting."

### Judge / Sponsor Judge: `/judging/[hackathonId]/[submissionId]`
- Submission detail: repo/demo links, description, video if provided, team members.
- Per-dimension scoring panel: for each in-scope dimension, show the AI's score and rationale (rationale streams in on first load if not yet cached — this is the one place sustained motion is justified, since it's showing real generation happening), then a score input pre-filled with the AI's number, editable by the judge, plus an optional comment field.
- If the judge's number differs from the AI baseline past the threshold, show a small "differs from AI score" indicator next to that dimension — informational, not a warning, so judges aren't discouraged from disagreeing.
- **Submit score** → not destructive, so no confirm dialog needed, but show a clear "Scores submitted" state with a timestamp and let the judge edit until the hackathon's judging deadline closes.

### Head Judge only: `/judging/[hackathonId]/winners`
- Per track, per prize: leaderboard of submissions ranked by weighted score, with the option to select a winner (auto-suggested top scorer, but overridable — ties or close scores should surface a note).
- **Select winner** → creates a `WinnerSelection` in `DRAFT` status, visible but not public.
- **Confirm all winners** → the highest-stakes confirm dialog in the whole system: "Confirming winners for [Hackathon Name] will publish results publicly and lock all winner selections. This cannot be undone through the platform. Continue?" — matches Devfolio's actual rule that winners can't be edited post-confirmation without contacting support directly, which is a deliberate design choice worth keeping: it forces organizers to actually double-check before confirming.

### Student/team side (small additions to the existing submission flow)
- Submission form gains a multi-select: "Opt into sponsor tracks" (shows track name + prize summary for each, so teams understand what they're opting into).
- Results page, once published, shows the per-dimension breakdown for their own submission (AI rationale + final score), not just a single number — this is the payoff for building the rubric system in the first place: participants get to see *why*, not just *what*.
